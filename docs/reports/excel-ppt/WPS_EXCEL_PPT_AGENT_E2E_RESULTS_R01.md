# Excel / PPT Windows Agent 端到端测试盘点（R01）

测试日期：2026-09-18。依据本轮 22 个会话公开工具记录、63 个持久化 Task Response、1 个无 taskId 的入口拒绝响应以及关联 timing 日志。仅做证据收集和统计，没有重跑、修改文档或清除隔离记录。

## 结论

按最终交付回执口径：Excel 9/10，PPT 10/10，合计 **19/20（95%）**。XE10 未交付。这个数字包含 Agent 的重试、返工以及绕过隔离后的成功，**不代表一次编排成功率或预定流程遵守率**。20 例人工粗审均待用户反馈；当前不能写成人工验收通过。

按所有提交的 Task Response 统计，**52/64 成功（81.25%）**；已准入执行 Task 为 52/63（82.54%），另有 1 次入口拒绝。按实际有 Action Response 的操作统计，**772/781 成功（98.85%）**。不能将这些写成 100%。

20 例端到端累计 4366.4 秒，准入 Task 累计 1634.2 秒（约 37.4%）；差额约 2732.2 秒包括 Agent 生成、查 schema、工具调用、诊断、渲染、写记忆及回复等，不能全部称为“模型思考时间”。并发时各例时长会重叠，累计值不等于本轮墙钟时长。

通信计时：

- 全部桥接往返累计 1455.4 秒，**含 WPS 执行、等待和超时，不能当作纯通信**。
- 按 `bridgeRequestId + operation + 时间窗口` 匹配，1739 次桥接中 1731 次具有完整原生阶段记录。完整样本往返 1196.7 秒，原生处理阶段 1076.3 秒，差额约 120.4 秒；其中 Excel 36.9 秒、PPT 83.5 秒。
- 上述差额是传输、调度、日志等未覆盖开销的估算，**不是网络延迟**。8 次记录不完整（含超时/退出等）不硬拆分，其往返约 258.8 秒。
- Action 时间包含桥接，Task 时间包含 Action；这些嵌套指标不能相加。每 Action 原始耗时见 actions.csv。

## 关键问题与证据

### 1. 本轮不是原计划的串行、独立环境测试

正式会话最多 13 个时间区间重叠，执行请求计时最多 8 个重叠。宿主每例使用独立 WorkBuddy 工作目录，但共享 WPS 进程、协调目录、用户级记忆。性能结果只能代表本轮并发现场，不能直接与此前串行执行层测评比较。

XE06 的公开工具记录证明 Agent 在北京时间 **21:48:15.046** 调用 `Stop-Process -Id 34428 -Force`；随后读取 repair1.txt 确认 `killed 34428`。XE10 `w_data/writeRange` 从 **21:47:23.915** 到 **21:48:15.857**，最终 RPC 失败。两者发生在同一秒，是跨用例进程干扰的强相关证据；尚未单独证明 XE10 绑定的就是该 PID，不能把相关性写成最终根因，也不能直接声称 WPS 自发崩溃。

### 2. Agent 违反了失败即报告的边界

XE06 强杀进程并删除两条协调记录；XE08 备份后删除隔离记录；XE09 移动记录并重试。只确认 ownerPid 退出不等于证明 WPS 操作已静默，不能把这类绕过当作保护机制正常恢复。XE09 还新建用户级 `wps-office-automation-recovery` Skill，XE06 等修改了 `.workbuddy/MEMORY.md`，把这些恢复做法写入共享记忆。这是后续测试的环境污染；本次盘点未删除或修改它们。

XE03、XE06、XE08、XE09 的 readRange 超时均有 `cleanup.outcome=failed`；是执行/资源清理问题的真实观测，需要串行受控复现后定因。Agent 关于“冷启动超过 60 秒”的解释不是本报告已证明的事实。

### 3. PPT 的主要返工点在编排与接口理解

- PE05：引用路径用了负整数索引，入口 `INVALID_TASK_REQUEST` 拒绝，后续改正成功。
- PE06：在同一已有文稿留下未保存修改，再以新 Task 保存，触发 `TASK_EXISTING_CHANGES_CONFIRMATION_REQUIRED`。后续加入 `includeExistingChanges` 成功；用户期间没有额外确认消息，属于需要审查的 Agent 行为。
- PE10：`gsTb` 引用了不存在的 `r2.data.shapes[3].id`，Task 在准备阶段 `TASK_REFERENCE_UNAVAILABLE` 停止；尚未执行该 Action。
- PE07：初版将第二页内容写在第一页，回执全成功，因为执行层正确执行了错误目标参数。这说明回执不能代替自然语言内容验收；用户粗审仍然必要。
- PE04/PE08/PE10：Agent 在预览后报告 RGB/BGR 配色理解错误并返工。已证实存在改色过程；接口说明归因应结合实际查询输出进一步审查，不能仅凭 Agent 自述确定“COM bug”。

### 4. 非执行工作仍明显偏多

20 个正式会话共调用查询脚本 49 次，其中 4 次自行加管道。记录还出现 head/tail/dirname 不存在、PowerShell 输出绕行、对多行 CLI 输出整体 JSON 解析出错。Agent 多次额外导出预览、解包 XML、写长期记忆、追问昵称等。这些都拉长端到端时间；不应记为 WPS Action 执行时间。

## 覆盖与证据限制

- XE01 提交前截图确认模型为 Deepseek-V4.1-Flash；手动部分日志未提供可独立核实的逐会话模型元数据，因此不能声称已逐例验证模型固定。
- 正式用例均可确认读取目标 Skill：19 个有对应 Skill 工具调用，PE01 直接 Read 安装的 wps-ppt/SKILL.md；PE01 还读取了宿主内置文档路由 Skill。
- 本轮没有重新打开文件做人工视觉评判，也没有额外调用 WPS 回读。最终交付依据已有 Task Response 的保存/导出成功和文件目录记录。
- 20 个正式用例都保留实际失败和返工，不以末次成功覆盖早先错误；两个无执行 Task 的中断会话单列。

## 后续建议（尚未执行）

优先恢复受控测试环境：先审阅并隔离 Agent 自建的恢复 Skill 和共享记忆中的绕过规则，明确失败后只能报告、不能强杀或清理协调记录。然后串行复测 XE03/XE06/XE08/XE09/XE10，确认超时/RPC 是否仍可复现；PPT 则针对负索引、页面/形状引用、颜色语义和跨 Task 保存分别验证。现阶段不扩大成功率结论。
