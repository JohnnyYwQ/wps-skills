# 不依赖宿主的设计实验

2026-09-19。先声明实验，再执行；本文件不是通过报告。使用当前工作区的独立包与固定 JSON，不改宿主安装包。最终价值仍按任务达成、完成效率、操作安全与结果可信评价；这里不能直接测 Agent 的任务完成率。

## 判断标准与范围

| 实验 | 最终维度 | 当前方案与对照/扰动 | 预先规定的判断 |
| --- | --- | --- | --- |
| schema 加载 | 效率 | 三应用同一组选定 Action：批量按需 vs 全量定义 | 所选契约一致；比较 UTF-8 字节、查询耗时，不换算未知模型 token |
| 结果引用 | 任务达成 | 三应用真实新建/打开、动态范围/工作表/slide ID、修改、保存 | 独立检查文档目标效果；错误引用的消费者不执行 |
| 尾部静态错误 | 安全可信 | 同计划，完整预检 vs 测试候选仅在执行每步时校验 | 正式方案零修改；候选记录错误前的修改，两组都不得误报完成 |
| 同路径不重放 | 安全可信 | 丢最终输出、同路径重复、并发重复；换路径作保证边界对照 | 同路径效果一次、同一身份，冲突内容拒绝；换路径确实是新执行 |
| 精确绑定 | 安全可信 | A 绑定后激活测试 B；Excel 另设按活动工作表取目标候选 | 正式方案只改 A；候选是否误改 B 由独立 COM 观察判定 |
| 原生回读 | 安全可信、效率 | Excel 受控跳过单元格赋值；真实回读 vs 乐观生成结果 | 正式方案检出效果不符并停止；候选的假成功用独立文件/COM 内容证实；记录代价 |
| 过期观察与动态非法参数 | 安全可信 | 观察后修改，再使用旧观察；另一个 Task 复用旧范围/token；引用合法但解析出的值不符合参数类型 | 消费者拒绝、后续不执行；已发生修改如实保留 |
| 持久回执与中断 | 安全可信 | 在效果前、效果后但响应前、保存后受控终止所拥有 Python | 查询保留已知结果；可能执行步骤不得假报未执行/成功；原提交不重放 |
| Lease、Quarantine 与有界返回 | 安全可信、失败成本 | 同文档竞争；协调操作窗口内已产生效果后挂起 bridge，触发 deadline | 竞争不进入；隔离后同文档拒绝、其他文档可用；桥接进程被回收；记录返回上界和保守阻塞代价 |
| 显式持久化和部分完成 | 安全可信 | 无保存、仅导出、已有脏修改；分别注入保存/PDF/清理失败 | 磁盘变化符合意图，部分完成与清理分别报告，停止位置准确 |
| Task 阶段成本 | 效率 | 固定文档、不同计划长度，记录启动、回读、回执、总时间 | 内容及响应正确后才比较；当前无公平逐 Action 接续接口，不报告相对节省轮次 |
| 启动层数与传输候选 | 效率、稳定性 | 纯协议夹具比较直接 Python 与 PowerShell 外层；匿名管道与本机候选保持相同载荷 | 消息一致、错误不能假报成功、有限时清理；只是协议/启动候选，不冒充 WPS 替代方案已成熟 |
| 持续通信 | 效率、稳定性 | 现行生产 transport，7200 秒反复创建、中文/Unicode 应答、关闭 | 所有载荷一致、所属进程清理成功；失败即停；记录实际时长和样本数 |

## 实施约束

- 可重复的正常和故障场景按三应用各 3 次为首轮目标；较重的中断窗口先各 1 次。成本按配对交替顺序重复，报告样本数、分布和运行条件，不给小样本总体保证。
- 故障和候选只存在于专用测试副本；记录补丁、原哈希、修改后哈希、具体注入点。没有实际触发注入的用例不能通过。
- 观察接口是 Task Request/Response、持久回执、真实测试文档、进程终态。故障钩子只是制造环境条件，不得直接伪造被测保护的通过结论。
- 独立读取真实文档和保存文件。测试文档有全局唯一文件名；仅成功保存且验证后的文档可以按精确路径关闭。失败现场保留，不退出 WPS。
- 并发和中断依赖明确的阶段信号，不靠猜测 sleep 时长。超时实验声明所模拟的是协调窗口内效果尚未确认，不把桥接等待冒充真实 WPS 内部原生调用卡死；后者没有证据就标未覆盖。
- 长时纯通信与文档实验可同时运行，属于有其他测试负载的环境；不称空闲机器性能。该长时测试不调用 COM，不证明 WPS 连续运行两小时稳定。
- 意外失败停止所属实验批次，定位后新目录复测；保留所有早期失败。预期失败按断言判断，不并入正常完成率。未实现、未触发或未完成的候选明确列出。

本轮持续通信配置为 `src/test/resources/diagnostics/design-value/pipe-long.json`；运行从 `startup-20260919T122809-b2034997` 开始。其他输入、对照与结果在各独立运行的清单和报告中落盘。

## 持久回执对照的具体化（执行前补充）

`receipts`：正式逐步回执 vs 只保留接纳记录与最终回执的测试候选。两组均新建独立 fixture，实际修改并保存后、PDF 派发前由阶段屏障停止所拥有 Python；各应用先 1 对。候选的接纳记录将全部步骤保守标为 unknown，避免用错误的“未执行”状态人为夸大对照。

两组磁盘均应保留一次标记，Task 查询均应 interrupted/unknown，旧路径均不得重放，bridge 均应退出。正式方案须保留已成功保存和其他已知步骤；候选只保留整体未知。比较回执中 `succeeded` 与 `unknown` 数，不声称靠该实验测出了人的排障速度，也不把此候选安装给宿主。该候选的代码、配置和触发日志随测试包记录。

## 保存后的 Lease 连续性（执行前补充）

`lease_paths`：在实际 `save` 或 `saveAs` 返回后、所属 Task 尚未结束时暂停 owner，另一个 Python 提交同一保存目标。三应用、两种保存方式各先 1 次。竞争者应收到 `DOCUMENT_LEASE_CONFLICT`；释放 owner 屏障后保存任务成功且标记仍只有一次。Save As 还独立确认原文件没有标记。此项检验保存后新路径/文件状态仍受围栏约束，不推导覆盖所有重命名或文件系统别名。
