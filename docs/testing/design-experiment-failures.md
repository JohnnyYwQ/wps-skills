# 设计实验的早期失败与修复

本文件记录实验工具和对照构造的问题。失败批次停止且保留；不把修复后的新批次覆盖到旧证据，也不计为产品 Task/Action 失败率。

## native-pilot-v2：Excel 活动表候选不是单因素路径

预检和防重放三应用全部通过，Word 精确绑定通过。Excel 正式方案正确；候选把缓存工作表目标切到 B 后执行 `insertRows`，B 的 BASE 从 A1 移到 A2，A 保持原样。结构修改后的资源失效使回读重新绑定 A，报 `RANGE_WRITE_FAILED`、Task `unknown`，未保存；批次停止。

这说明该候选产生了误改，且现有回读检出了不一致。它不能作为“持续按活动表读写”的公平对照。v3 将两组都改为不触发结构缓存失效的单元格写入；其正式组只改 A、候选组只改 B，两组 Task 均返回成功。B 的独立观察暴露候选的错误目标。v2、v3 原始证据均在 `build/runs/design-value/`，分别验证 602、703 个文件哈希。

## 证据收集工具：文件共享与 PowerShell 路径转义

初版收集器直接 `Get-FileHash`/压缩正在 WPS 中打开的测试文件，Windows 拒绝共享访问；另有反斜杠在 Python 字符串与 PowerShell 之间被消耗的问题。修复为显式共享读/写/删除权限复制独立快照，再对快照计算哈希、归档；路径转换使用字符码。每次归档新建身份，避免误用失败产生的半成品 ZIP。没有关闭失败文档，也没有改写原始证据。

## startup-20260919T122809-b2034997：长测监督器状态发布失败

12:28:25–12:36:31 UTC，1773 轮纯通信通过，每轮验证两个中文/Unicode 载荷并清理所属进程。准备发布第 1774 轮的状态时出现 `PermissionError`，留下含该轮的 `status.json.*.tmp`；本轮子进程尚未启动。此前状态文件仍是 `running`。外层 PowerShell 把 Python stderr 首行当作终止错误，完整 traceback 未被保留。此运行**不是两小时通过**，只保留为未完成的早期证据。

在 Windows 临时文件上，用不允许删除共享的真实读句柄重现 `os.replace` 的 WinError 5；修复后同一回归用例等待约 0.36 秒并成功。该复现证明状态发布对短暂读取锁脆弱，不能由此确认原现场的具体锁持有者。

修复只涉及诊断工具：状态发布对 Windows 短暂共享冲突最多等待两秒；状态只保留最近 50 轮和累计数，完整结果追加到 `cases.jsonl`，避免整段历史被反复重写；故障 traceback 独立写文件，外层用原生进程输出重定向保留 stderr。没有重试通信消息、Task 或 Action。17 个本地回归通过，Windows 真实锁回归通过，新的快速检查 10/10 通过并完成哈希归档。后续运行 `startup-20260919T125109-a3b38145` 在 6118 轮通过、0 轮失败后按用户要求停止，实际约 28 分 53 秒，不计为两小时通过；本轮不再复测。

## protocol-cost-v5：TCP 夹具缓冲差异

三个候选的正确性与故障断言均通过，但 TCP 4096 字符往返约 15 ms。检查发现其服务端使用无缓冲 `readline`，与匿名管道和命名管道的读取方式不等价。v6 改为缓冲行读取并显式 flush 后重新运行全部协议用例。v5 的慢数据保留为该实现的结果，不推导“TCP 固有较慢”。

## receipt-lease-v12：测试日志读取依赖了系统编码

Word 的逐步回执/最终回执对照通过；Excel 候选在中断和回执查询完成后，驱动用未指定编码的 `Path.read_text()` 读取 UTF-8 `child-events.jsonl`，触发 GBK 解码失败，批次立即停止。Word 该日志中的响应数据主要为坐标等 ASCII 字段，未暴露此问题；Excel 单元格响应含中文。修复为显式 UTF-8-sig，并用新包、新目录重新执行整批，`receipt-lease-v13` 九组均通过。它说明测试工具也必须固定文本编码，不能据此判定生产 Action 或通信失败。
