# 复杂业务测试脚本复审

2026-09-19，按用户要求从“整个批次失败即停止”改为三个独立应用脚本自动完成后统一分析。正式执行版本 R07；早期调试轮次原样保留。

## 结论与改动

此前慢的主要原因是测试入口在任意断言失败时退出整个批次，修复测试请求后又重跑所有前置步骤，导致 Excel/PPT 始终没有机会运行。新测试还存在目录打包、文字范围、查询上限和段落锚点假设错误。这些属于测试准备与编排问题，不能归咎于执行端性能。

测试包现在只提供三个 Python 入口：`run_word.py`、`run_excel.py`、`run_ppt.py`。各入口可以直接运行，无需先执行 prepare 命令：自动建立唯一目录、生成请求和预期、准备素材、顺序执行 20 个业务 Task 并写出报告。多个入口共享底层实现，避免三份断言逻辑分叉。

- 普通断言失败、或已终止且资源清理成功的 Task 失败：保留失败结果，继续下一独立用例，无自动重试。
- 素材失败：只阻塞依赖该素材的业务用例，标记 blocked，其余用例继续。
- 子进程超时、缺少可信终态、清理未确认：停止该应用，未执行项保持 not_run；不跳过其他独立应用脚本。
- 每个业务 Task 内部仍遵守产品的失败停止语义，绝不跳过失败 Action 继续写入同一文档。
- 桌面启动器依次运行三个入口，不因某个入口非零退出而取消后两个。
- 失败用例的未保存文档保留，测试不会全局关闭 WPS 或解除隔离。

## 请求与断言复查

1. 输出目录由应用脚本在 WPS 操作前建立，ZIP 同时包含空目录条目。
2. Word 字体按实际文字范围读取；段落标记的混合字体不冒充文字字体。保留文本、字号、加粗、中西文字体和段落格式的确定断言。
3. 分批追加内容允许执行器为结构化段落加入一个前导分段符，正文必须精确匹配；不接受任意删减或截断。
4. 查找数量由固定输入推导，查询上限必须覆盖预期数量；结果引用选择固定输入对应的命中，避免重复标题造成索引错误。
5. CW15 插入点改为目标正文段落开头，符合结构化段落的锚点规则；业务位置仍在风险标题之后。
6. CW14 素材末段设置加粗，确保续写测试实际覆盖不继承加粗的要求。
7. CE18 增加工作表最终顺序断言；CP10 增加未修改页面的内容断言；CP19 初始表格与更新值分开保存，防止共享可变列表让两次输入意外相同。
8. 每例固定 JSON 和独立 expected，正式契约预检、引用校验、结果字段路径校验及每 Action 数据断言全部完成。三应用 20/20/20、正式 Action 覆盖 14/34/37。

## 验证与实机范围

本地应用测试 23 项通过。新增调度测试驱动真实批次循环的子进程/响应边界，分别证明普通失败后不重试并继续、只阻塞素材依赖、超时停止、清理未确认停止。

R07 的 60 个业务 Task 计划包含 Word 330、Excel 420、PPT 743 次 Action，合计 1493 次。另有 14 个 setup Task，不混入业务完成率和耗时。各轮 `src/main` 的 254 个生产文件哈希一致；本次修改仅涉及测试工具和文档。

本轮请求、预期与包均在 Windows 执行前冻结。运行过程中不改断言、不重跑整个批次，结束后统一分析成功、失败、blocked、not_run 和成功业务 Task 的执行时间。响应断言通过不代表页面视觉验收或真实 Agent 自主完成率。

## 使用

解压 `complex-business-20260919-r07.zip`，在已登录 Windows 桌面的终端依次执行：

```powershell
python run_word.py
python run_excel.py
python run_ppt.py
```

无参数时各自创建唯一目录；可用 `--root C:/wps-tests/本轮唯一目录` 指定。一个目录仅执行一次，不自动重放历史任务。
